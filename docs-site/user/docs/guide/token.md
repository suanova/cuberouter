# API 密钥管理

> 密钥（Token）是调用 API 的凭证，每个密钥可独立配置权限范围和配额上限。

::: warning 重要提醒
API 密钥是调用 CubeRouter 服务的凭证，请务必妥善保管，不要泄露给他人。
:::

左侧导航点击「API 密钥」，或直接访问 `/keys`。

![API 密钥列表](/imgs/token-list.jpeg)

## 什么是 API 密钥？

**API 密钥**是一个唯一的识别符，用于：

- 🔐 **身份验证**：证明你有权使用 CubeRouter 服务
- 📊 **用量统计**：记录每个密钥的使用量和消费情况
- 🎯 **权限控制**：限制每个密钥可以访问的模型
- 💰 **计费管理**：根据使用量进行计费

每个密钥都像一个"虚拟账户"，可以独立管理权限和计费。

## 密钥列表

API 密钥页面的核心是密钥列表，展示所有已创建的密钥。

### 列表字段

| 字段名称 | 说明 |
| --- | --- |
| 名称 | 密钥的自定义名称，便于识别用途 |
| 状态 | 密钥的当前状态（已启用 / 已禁用） |
| API 密钥 | 密钥字符串（支持复制、显示 / 隐藏） |
| 额度 | 该密钥已消耗的额度 |
| 分组 | 密钥所属的渠道分组 |
| 模型 | 密钥可访问的模型限制 |
| IP 限制 | 密钥的 IP 白名单设置 |
| 创建时间 | 密钥创建的时间 |
| 最后使用时间 | 密钥最近一次被使用的时间 |
| 过期 | 密钥的过期时间 |
| 操作 | 可执行的操作（禁用 / 编辑 / 删除等） |

### 空状态提示

当没有创建任何密钥时，页面会显示友好提示，建议创建第一个密钥开始使用。

## 创建密钥

点击「创建 API 密钥」按钮，可以创建新的 API 密钥。

![创建 API 密钥](/imgs/token-create.jpeg)

### 基本配置

1. 点击「创建 API 密钥」按钮
2. 填写密钥「名称」：建议按用途命名（如 `prod`、`dev-test`、`team-member-name`）
3. 选择「分组」：不同分组可访问的模型不同
4. 设置「过期时间」：可选择永不过期，或使用预设（1 个月 / 1 天 / 1 小时）
5. 设置「数量」：可批量创建多个密钥（默认为 1 个）
6. 开启「无限配额」则不受配额限制，否则可设置该密钥可用的最高额度
7. 点击「创建」

### 高级设置

展开「高级设置」可配置以下选项：

| 配置项 | 说明 |
| --- | --- |
| 模型限制 | 限定该密钥只能调用指定模型，留空表示不限制 |
| IP 白名单 | 限定允许使用该密钥的来源 IP（CIDR 格式），留空表示不限制 |

### 保存密钥 Key

点击「创建」后，弹窗显示完整的密钥 Key，**立即复制保存**，关闭弹窗后无法再次查看完整 Key。

::: warning 重要提醒
密钥 Key 仅在创建时完整显示一次，请立即复制保存。密钥 Key 具有完整的 API 调用权限，请勿泄露给他人，不要提交到代码仓库或公开分享。
:::

## 密钥操作

每个密钥都支持以下操作：

### 复制密钥

- 一键复制完整的 API 密钥
- 方便快速配置到应用中
- 复制成功后有提示反馈

### 查看 / 隐藏密钥

- 默认密钥是隐藏的（显示为 `sk-****...****`）
- 点击眼睛图标可查看完整密钥
- 再次点击可隐藏密钥

### 编辑密钥

- 修改密钥名称
- 调整额度限制
- 更新模型限制
- 更改过期时间

### 禁用 / 启用密钥

- **禁用**：临时停用密钥，不影响数据
- **启用**：重新启用已禁用的密钥
- 用途：调试、安全控制、临时限制

### 删除密钥

- 永久删除密钥
- 删除后无法恢复
- 使用该密钥的应用将无法访问 API

## 额度管理

### 额度类型

每个密钥有两种额度：

- **已用额度**：该密钥已经消耗的总额度
- **剩余额度**：该密钥还可以使用的额度

### 额度限制

可以为每个密钥设置额度上限：

- **无限制**：使用账户总余额
- **固定额度**：设置具体的额度上限
- **实时监控**：超出限制后自动停用

## 状态说明

| 状态 | 说明 | 可用性 |
| --- | --- | --- |
| 已启用 | 密钥正常工作，可以调用 API | ✅ 可用 |
| 已禁用 | 密钥被临时停用 | ❌ 不可用 |
| 已过期 | 密钥超过有效期 | ❌ 不可用 |
| 额度不足 | 密钥额度已用完 | ❌ 不可用 |

## 使用场景

### 场景 1：个人开发

1. 创建一个密钥用于开发测试
2. 设置较小的额度限制
3. 开发完成后禁用或删除

### 场景 2：生产环境

1. 创建专用的生产环境密钥
2. 配置合适的额度上限
3. 设置 IP 白名单提高安全性
4. 定期监控使用情况

### 场景 3：团队协作

1. 为每个团队成员创建独立密钥
2. 便于追踪每个人的使用情况
3. 成员离职时删除对应密钥

### 场景 4：多项目管理

1. 为每个项目创建独立密钥
2. 单独控制每个项目的预算
3. 项目结束删除对应密钥
4. 清晰的成本分摊

## 最佳实践

### 安全建议

1. **命名规范**：使用清晰的命名标识密钥用途（如 `prod-api-v1`、`dev-test`）
2. **定期轮换**：定期更换生产环境的 API 密钥，建议每 3-6 个月更换一次
3. **最小权限**：只授予必要的权限，限制可访问的模型范围
4. **监控告警**：设置额度使用告警，接近上限时及时通知

### 使用建议

1. **环境隔离**：不同环境使用不同密钥（开发、测试、生产分离）
2. **额度控制**：为每个密钥设置合理的额度上限，避免意外超支
3. **及时清理**：定期清理不再使用的密钥
4. **备份记录**：妥善保管密钥信息，记录每个密钥的用途和创建时间

## 常见问题

### Q1: API 密钥忘记了怎么办？

API 密钥只在创建时显示一次。如果忘记了，需要删除旧密钥、创建新密钥、更新应用配置。

### Q2: 密钥额度用完了怎么办？

有两种解决方案：编辑密钥增加额度上限，或创建新密钥并更新应用配置。

### Q3: 如何查看密钥的使用明细？

前往「使用日志」页面，可查看每个密钥的详细调用记录，按密钥筛选日志，查看消耗统计。

### Q4: 多个应用可以共用一个密钥吗？

可以，但不推荐。建议每个应用使用独立密钥，便于权限管理、问题排查和成本分摊。

### Q5: 密钥泄露了怎么办？

立即禁用或删除泄露的密钥，创建新密钥，更新所有应用配置，检查异常使用记录。

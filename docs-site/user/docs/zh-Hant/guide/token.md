# API 金鑰管理

> 金鑰（Token）是調用 API 的憑證，每個金鑰可獨立配置權限範圍和配額上限。

::: warning 重要提醒
API 金鑰是調用 CubeRouter 服務的憑證，請務必妥善保管，不要洩露給他人。
:::

左側導航點擊「API 金鑰」，或直接訪問 `/keys`。

![API 金鑰列表](/imgs/token-list.jpeg)

## 什麼是 API 金鑰？

**API 金鑰**是一個唯一的識別符，用於：

- 🔐 **身份驗證**：證明你有權使用 CubeRouter 服務
- 📊 **用量統計**：記錄每個金鑰的使用量和消費情況
- 🎯 **權限控制**：限制每個金鑰可以訪問的模型
- 💰 **計費管理**：根據使用量進行計費

每個金鑰都像一個"虛擬賬戶"，可以獨立管理權限和計費。

## 金鑰列表

API 金鑰頁面的核心是金鑰列表，展示所有已創建的金鑰。

### 列表字段

| 字段名稱 | 說明 |
| --- | --- |
| 名稱 | 金鑰的自定義名稱，便於識別用途 |
| 狀態 | 金鑰的當前狀態（已啟用 / 已禁用） |
| API 金鑰 | 金鑰字符串（支援複製、顯示 / 隱藏） |
| 額度 | 該金鑰已消耗的額度 |
| 分組 | 金鑰所屬的渠道分組 |
| 模型 | 金鑰可訪問的模型限制 |
| IP 限制 | 金鑰的 IP 白名單設置 |
| 創建時間 | 金鑰創建的時間 |
| 最後使用時間 | 金鑰最近一次被使用的時間 |
| 過期 | 金鑰的過期時間 |
| 操作 | 可執行的操作（禁用 / 編輯 / 刪除等） |

### 空狀態提示

當沒有創建任何金鑰時，頁面會顯示友好提示，建議創建第一個金鑰開始使用。

## 創建金鑰

點擊「創建 API 金鑰」按鈕，可以創建新的 API 金鑰。

![創建 API 金鑰](/imgs/token-create.jpeg)

### 基本配置

1. 點擊「創建 API 金鑰」按鈕
2. 填寫金鑰「名稱」：建議按用途命名（如 `prod`、`dev-test`、`team-member-name`）
3. 選擇「分組」：不同分組可訪問的模型不同
4. 設置「過期時間」：可選擇永不過期，或使用預設（1 個月 / 1 天 / 1 小時）
5. 設置「數量」：可批量創建多個金鑰（默認為 1 個）
6. 開啟「無限配額」則不受配額限制，否則可設置該金鑰可用的最高額度
7. 點擊「創建」

### 高級設置

展開「高級設置」可配置以下選項：

| 配置項 | 說明 |
| --- | --- |
| 模型限制 | 限定該金鑰只能調用指定模型，留空表示不限制 |
| IP 白名單 | 限定允許使用該金鑰的來源 IP（CIDR 格式），留空表示不限制 |

### 保存金鑰 Key

點擊「創建」後，彈窗顯示完整的金鑰 Key，**立即複製保存**，關閉彈窗後無法再次查看完整 Key。

::: warning 重要提醒
金鑰 Key 僅在創建時完整顯示一次，請立即複製保存。金鑰 Key 具有完整的 API 調用權限，請勿洩露給他人，不要提交到代碼倉庫或公開分享。
:::

## 金鑰操作

每個金鑰都支援以下操作：

### 複製金鑰

- 一鍵複製完整的 API 金鑰
- 方便快速配置到應用中
- 複製成功後有提示反饋

### 查看 / 隱藏金鑰

- 默認金鑰是隱藏的（顯示為 `sk-****...****`）
- 點擊眼睛圖標可查看完整金鑰
- 再次點擊可隱藏金鑰

### 編輯金鑰

- 修改金鑰名稱
- 調整額度限制
- 更新模型限制
- 更改過期時間

### 禁用 / 啟用金鑰

- **禁用**：臨時停用金鑰，不影響數據
- **啟用**：重新啟用已禁用的金鑰
- 用途：調試、安全控制、臨時限制

### 刪除金鑰

- 永久刪除金鑰
- 刪除後無法恢復
- 使用該金鑰的應用將無法訪問 API

## 額度管理

### 額度類型

每個金鑰有兩種額度：

- **已用額度**：該金鑰已經消耗的總額度
- **剩餘額度**：該金鑰還可以使用的額度

### 額度限制

可以為每個金鑰設置額度上限：

- **無限制**：使用賬戶總餘額
- **固定額度**：設置具體的額度上限
- **實時監控**：超出限制後自動停用

## 狀態說明

| 狀態 | 說明 | 可用性 |
| --- | --- | --- |
| 已啟用 | 金鑰正常工作，可以調用 API | ✅ 可用 |
| 已禁用 | 金鑰被臨時停用 | ❌ 不可用 |
| 已過期 | 金鑰超過有效期 | ❌ 不可用 |
| 額度不足 | 金鑰額度已用完 | ❌ 不可用 |

## 使用場景

### 場景 1：個人開發

1. 創建一個金鑰用於開發測試
2. 設置較小的額度限制
3. 開發完成後禁用或刪除

### 場景 2：生產環境

1. 創建專用的生產環境金鑰
2. 配置合適的額度上限
3. 設置 IP 白名單提高安全性
4. 定期監控使用情況

### 場景 3：團隊協作

1. 為每個團隊成員創建獨立金鑰
2. 便於追蹤每個人的使用情況
3. 成員離職時刪除對應金鑰

### 場景 4：多項目管理

1. 為每個項目創建獨立金鑰
2. 單獨控制每個項目的預算
3. 項目結束刪除對應金鑰
4. 清晰的成本分攤

## 最佳實踐

### 安全建議

1. **命名規範**：使用清晰的命名標識金鑰用途（如 `prod-api-v1`、`dev-test`）
2. **定期輪換**：定期更換生產環境的 API 金鑰，建議每 3-6 個月更換一次
3. **最小權限**：只授予必要的權限，限制可訪問的模型範圍
4. **監控告警**：設置額度使用告警，接近上限時及時通知

### 使用建議

1. **環境隔離**：不同環境使用不同金鑰（開發、測試、生產分離）
2. **額度控制**：為每個金鑰設置合理的額度上限，避免意外超支
3. **及時清理**：定期清理不再使用的金鑰
4. **備份記錄**：妥善保管金鑰資訊，記錄每個金鑰的用途和創建時間

## 常見問題

### Q1: API 金鑰忘記了怎麼辦？

API 金鑰只在創建時顯示一次。如果忘記了，需要刪除舊金鑰、創建新金鑰、更新應用配置。

### Q2: 金鑰額度用完了怎麼辦？

有兩種解決方案：編輯金鑰增加額度上限，或創建新金鑰並更新應用配置。

### Q3: 如何查看金鑰的使用明細？

前往「使用日誌」頁面，可查看每個金鑰的詳細調用記錄，按金鑰篩選日誌，查看消耗統計。

### Q4: 多個應用可以共用一個金鑰嗎？

可以，但不推薦。建議每個應用使用獨立金鑰，便於權限管理、問題排查和成本分攤。

### Q5: 金鑰洩露了怎麼辦？

立即禁用或刪除洩露的金鑰，創建新金鑰，更新所有應用配置，檢查異常使用記錄。

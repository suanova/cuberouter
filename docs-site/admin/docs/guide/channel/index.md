# 渠道管理

渠道管理是 CubeRouter 的核心功能，用于配置和管理各类 AI 模型提供商的 API 接入渠道。每条渠道对应一个服务商的 API Key，通过渠道管理，管理员可以灵活地添加、编辑、测试和监控多个 AI 服务提供商。

使用管理员账号登录后，左侧导航点击「渠道」，或直接访问 `/console/channel`。

::: warning 合规提示
上游渠道必须是部署方合法拥有或已获授权的账号、API Key、模型服务或企业合约。负载均衡、故障自动切换、加权随机、多密钥管理等功能用于高可用和企业多账号管理，使用时应遵守上游服务条款、平台规则和监管要求。
:::

## 渠道配置

### 基本配置

1. 在渠道列表页点击右上角「添加渠道」按钮，弹出配置弹窗
2. 在弹窗中选择服务商类型（如 OpenAI、Claude、Gemini 等）
3. 填写渠道名称和 API Key

![添加渠道弹窗(基础信息)](/imgs/channel-add-basic.png)

| 字段 | 必填 | 说明 |
|------|:----:|------|
| **渠道名称** | ✓ | 渠道的显示名称，便于识别和管理 |
| **渠道类型** | ✓ | AI 服务提供商类型 |
| **API Key** | ✓ | 服务提供商的 API 密钥 |
| **Base URL** | | 自定义 API 端点地址 |
| **模型列表** | ✓ | 该渠道支持的模型 |
| **用户组** | | 可访问该渠道的用户组 |

### 选择模型

在模型列表中勾选该渠道支持的模型，或点击「填入默认模型」自动填充。

### 高级配置

按需展开高级配置，填写以下可选项：

![添加渠道弹窗(高级配置)](/imgs/channel-add-advanced.png)

| 配置项 | 说明 |
| --- | --- |
| Base URL | 自定义接口地址，代理或私有部署时使用 |
| 优先级 | 数值越高越优先被选中，默认为 0 |
| 权重 | 同优先级下的随机权重，默认为 0 |
| 模型映射 | 将用户请求的模型名映射为实际模型名，JSON 格式 |
| 参数覆盖 | 强制覆盖请求中的某些参数，JSON 格式 |
| 自动禁用 | 开启后连续失败达到阈值时自动禁用该渠道 |

## 多 Key 模式

多 Key 模式允许一个渠道配置多个 API Key，系统自动轮询使用，单个 Key 失败后自动跳过，恢复后重新启用。

### 配置多 Key

1. 在渠道列表中点击目标渠道右侧的「编辑」按钮
2. 在编辑弹窗中找到「多 Key 管理」区域

![多 Key 模式配置区域](/imgs/channel-multikey.png)

3. 点击「添加 Key」逐条输入多个 API Key

### 选择轮询模式

| 轮询模式 | 说明 |
| --- | --- |
| **轮询（Round Robin）** | 按顺序依次使用每个 Key |
| **加权随机** | 按权重随机选择 Key |

::: tip 多 Key 最佳实践
- 建议配置 2-3 个 Key 以保障可用性
- 定期检查各 Key 的使用量和余额
- 不同 Key 可以来自不同账户，分散风险
:::

### 保存配置

点击「保存」完成配置。

## 渠道状态

| 状态 | 图标 | 说明 | 处理建议 |
|------|:----:|------|----------|
| **已启用** | 🟢 | 正常工作，处理请求 | 无需操作 |
| **已禁用** | 🔴 | 手动禁用，不处理请求 | 按需启用 |
| **自动禁用** | 🟡 | 连续失败被系统禁用 | 检查 Key 有效性或余额 |

::: warning 自动禁用机制
当渠道连续请求失败达到阈值时，系统会自动禁用该渠道。常见原因：

- API Key 失效或过期
- 账户余额不足
- 上游服务异常
- 请求频率超限

被自动禁用的渠道需手动重新启用，或在修复问题后自动恢复（取决于配置）。
:::

## 渠道测试

### 单个渠道测试

1. 在渠道列表中找到目标渠道，点击右侧操作栏中的「测试」按钮
2. 等待测试请求完成，弹窗显示响应时间和成功/失败状态

![渠道测试结果弹窗](/imgs/channel-test.png)

响应时间越短说明该渠道速度越快。测试成功后，响应时间会显示在渠道列表中，便于监控渠道性能。

### 批量测试

点击列表顶部「测试所有渠道」按钮一键批量测试。

::: tip 测试建议
- 新建渠道后立即测试，确保配置正确
- 定期测试渠道，及时发现异常
- 关注响应时间变化，评估服务质量
:::

## 权限设置

渠道支持按用户组进行访问控制：

| 用户组 | 说明 |
|--------|------|
| **default** | 默认用户组，所有用户可访问 |
| **vip** | VIP 用户组，仅 VIP 用户可访问 |
| **自定义组** | 管理员创建的自定义用户组 |

::: info 权限控制原理
用户请求模型时，系统会根据用户所属的用户组筛选可用的渠道。只有渠道配置的用户组与用户组匹配时，该渠道才会被纳入路由选择。
:::

## 模型映射

模型映射允许将用户请求的模型名称映射到实际使用的模型：

```json
{
  "gpt-4": "gpt-4-turbo",
  "gpt-3.5-turbo": "gpt-3.5-turbo-16k"
}
```

**常见用途**：
- 模型升级后保持兼容性（`gpt-4` → `gpt-4-turbo`）
- 统一不同提供商的模型命名
- 为用户提供简化的模型名称

详见 [高级设置 - 模型映射](./advanced#模型映射)

## 操作指南

### 新建渠道

1. 点击页面右上角的 **新建渠道** 按钮
2. 选择渠道类型
3. 填写必要信息：
   - 渠道名称
   - API Key
   - 支持的模型
4. 配置可选参数：
   - 用户组权限
   - Base URL（代理或私有部署时需要）
5. 点击 **提交** 保存

### 编辑渠道

1. 在渠道列表中找到目标渠道
2. 点击 **编辑** 按钮
3. 修改需要更新的配置
4. 点击 **保存** 确认修改

### 批量操作

支持选中多个渠道后进行批量操作：

1. 在渠道列表左侧勾选多条渠道的复选框
2. 页面顶部出现批量操作工具栏

![勾选多条渠道后的批量操作栏](/imgs/channel-batch.png)

3. 点击对应按钮执行批量操作：

| 操作 | 说明 |
|------|------|
| **批量启用** | 一次性启用多个渠道 |
| **批量禁用** | 一次性禁用多个渠道 |
| **批量打标签** | 为选中渠道统一设置标签，便于分类管理 |
| **批量删除** | 删除选中的渠道（不可恢复） |

::: danger 批量删除警告
批量删除操作不可恢复，请谨慎操作。建议先禁用观察，确认无误后再删除。
:::

## 注意事项

::: warning API Key 安全
- 不要在公开场合分享 API Key
- 定期轮换 API Key
- 使用环境变量或密钥管理服务存储 Key
:::

::: tip 运维建议
- **余额监控**：定期检查渠道余额，避免服务中断
- **响应时间**：关注渠道响应时间变化，及时发现性能问题
- **多渠道备份**：关键模型配置多个渠道，保障服务可用性
- **标签分类**：使用标签对渠道分类，便于管理大量渠道
:::

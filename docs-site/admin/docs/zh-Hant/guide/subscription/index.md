# 訂閱管理

訂閱管理用於創建和管理訂閱套餐，用戶購買訂閱後可獲得一定期限內的服務權益，包括額度、用戶組升級等特權。

使用管理員賬號登錄後，直接訪問 `/console/subscription`（管理員視角與用戶購買界面不同）。

![訂閱計劃管理列表](/imgs/sub-admin-list.png)

套餐列表展示所有已創建的訂閱套餐，包含名稱、價格、有效期、狀態（上架 / 下架）等資訊。

## 訂閱方案配置

### 基本資訊

![創建訂閱套餐彈窗](/imgs/sub-create.png)

| 字段 | 必填 | 說明 |
|------|:----:|------|
| **方案標題** | ✓ | 訂閱方案的顯示名稱，如「月度會員」、「年度會員」 |
| **方案副標題** | | 補充描述資訊，如「適合個人用戶」 |
| **價格金額** | ✓ | 訂閱價格 |
| **貨幣類型** | ✓ | 價格的貨幣單位，預設 USD |
| **啟用狀態** | | 是否啟用該方案 |

::: tip 命名建議
- **簡潔明瞭**：如「月度基礎版」、「年度專業版」
- **突出價值**：如「無限暢享月卡」、「尊享年度會員」
- **統一風格**：保持所有方案命名風格一致
:::

### 有效期設置

訂閱方案支援多種有效期單位：

| 單位 | 說明 | 適用場景 |
|------|------|----------|
| **小時** | 按小時計費 | 臨時體驗、短期試用 |
| **日** | 按天計費 | 短期活動、體驗套餐 |
| **月** | 按月計費 | 標準訂閱週期 |
| **年** | 按年計費 | 長期會員、優惠套餐 |
| **自定義** | 自定義秒數 | 特殊週期需求 |

**配置示例**：

| 方案 | 有效期單位 | 數值 | 實際有效期 |
|------|:----------:|:----:|:----------:|
| 體驗版 | 日 | 3 | 3 天 |
| 月度會員 | 月 | 1 | 30 天 |
| 季度會員 | 月 | 3 | 90 天 |
| 年度會員 | 年 | 1 | 365 天 |

::: warning 有效期計算
- 月按 30 天計算
- 年按 365 天計算
- 自定義時直接輸入秒數（如 86400 = 1 天）
:::

### 額度設置

額度是用戶使用 AI 服務的計量單位，訂閱方案可包含一定額度供用戶使用。

| 字段 | 說明 |
|------|------|
| **總額度** | 訂閱包含的總額度，0 表示不限制 |
| **額度重置週期** | 額度重置的時間間隔 |

**重置週期選項**：

| 選項 | 說明 | 適用場景 |
|------|------|----------|
| **不重置** | 額度用完為止，不自動恢復 | 一次性額度包 |
| **每天** | 每日 00:00 重置額度 | 高頻使用場景 |
| **每週** | 每週一重置額度 | 週期性需求 |
| **每月** | 每月 1 日重置額度 | 標準訂閱模式 |
| **自定義** | 指定間隔秒數重置 | 特殊需求 |

::: info 額度重置行為
- 重置時額度恢復到初始值，不是累加
- 用戶未用完的額度不會累積
- 重置時間基於伺服器時區
:::

### 用戶組升級

訂閱方案可以配置購買後自動升級用戶組：

| 設置 | 說明 |
|------|------|
| **升級分組** | 購買後自動升級到的用戶組名稱 |
| **留空** | 不升級用戶組，保持原用戶組 |

::: tip 用戶組與渠道權限
用戶組決定了用戶可以訪問哪些渠道。通過訂閱升級用戶組，可以實現：
- 普通用戶 → VIP 用戶（解鎖高級模型）
- 體驗用戶 → 正式用戶（解鎖更多功能）
:::

### 購買限制

| 字段 | 說明 |
|------|------|
| **用戶購買上限** | 單個用戶最多可購買的次數，0 表示不限制 |

**應用場景**：

| 上限設置 | 適用場景 |
|----------|----------|
| 0（不限） | 標準方案，可多次購買延長有效期 |
| 1 | 限時優惠、新人專享 |
| N | 限制購買次數的促銷活動 |

## 支付集成

訂閱方案支援對接多種支付平臺，實現自動化訂閱購買。支付平臺的 API 金鑰配置見 [系統設置 - 支付設置](../system/index#支付設置)。

### Stripe 集成

Stripe 是國際主流支付平臺，支援信用卡等多種支付方式。

**配置步驟**：

1. 在 Stripe 後臺創建產品和價格
2. 獲取 Price ID（格式：`price_xxxxx`）
3. 在訂閱方案中填寫 **Stripe Price ID**
4. 確保已在系統設置中配置 Stripe API 金鑰

::: details Stripe Price ID 獲取方式
1. 登錄 [Stripe Dashboard](https://dashboard.stripe.com/)
2. 進入 Products 頁面
3. 選擇對應產品
4. 在 Pricing 區域找到 Price ID
:::

### 其他支付方式

平臺還支援 **EPay（易支付）** 等聚合支付方式，具體配置方法見 [系統設置 - 支付設置](../system/index#支付設置)。

::: warning 支付配置順序
1. 先在系統設置中完成支付平臺的 API 配置
2. 再在訂閱方案中關聯對應的價格/產品 ID
3. 最後進行測試支付驗證配置正確性
:::

## 操作指南

### 創建訂閱方案

1. 在訂閱管理頁點擊「創建套餐」按鈕，彈出創建彈窗
2. 填寫方案基本資訊
   - 方案標題和副標題
   - 價格金額和貨幣類型
3. 配置有效期
   - 選擇有效期單位
   - 設置有效期數值
4. 配置額度
   - 設置總額度
   - 選擇重置週期
5. 配置其他選項
   - 用戶組升級
   - 購買限制
   - 支付集成 ID
6. 點擊「提交」，套餐創建完成並預設處於下架狀態

### 上架 / 下架套餐

1. 在套餐列表中找到目標套餐，點擊右側「上架」或「下架」按鈕

![套餐上架/下架操作](/imgs/sub-publish.png)

2. 上架後用戶在訂閱頁可看到併購買該套餐；下架後套餐對用戶不可見，但已購買的訂閱不受影響

### 編輯訂閱方案

1. 在方案列表中找到目標方案
2. 點擊 **編輯** 按鈕
3. 修改需要更新的配置
4. 點擊 **保存** 確認修改

::: warning 修改影響
- 修改方案配置後，**新購買**的用戶使用新配置
- **已購買**的用戶不受影響，繼續使用原配置
- 如需調整已購買用戶的權益，需通過用戶管理手動處理
:::

### 排序管理

- 設置方案的排序值，**數值越大越靠前**
- 調整後用戶端按排序值顯示方案列表
- 建議將推薦方案排序值設高

**排序建議**：

| 方案 | 排序值 | 顯示位置 |
|------|:------:|:--------:|
| 年度會員（推薦） | 100 | 第 1 位 |
| 季度會員 | 50 | 第 2 位 |
| 月度會員 | 10 | 第 3 位 |
| 體驗版 | 1 | 第 4 位 |

## 用戶訂閱管理

### 管理員視角

管理員可以在用戶管理頁面查看用戶的訂閱狀態：

| 狀態 | 說明 |
|------|------|
| 🟢 **活躍訂閱** | 當前有效的訂閱 |
| ⚪ **過期訂閱** | 已過期的訂閱歷史 |

### 為用戶手動開通訂閱

1. 在訂閱管理頁點擊「手動綁定」按鈕
2. 輸入目標用戶名或郵箱，選擇要開通的套餐
3. 點擊「確認」，系統為該用戶創建訂閱記錄，立即生效

### 用戶端功能

用戶在訂閱管理頁面可以：

| 功能 | 說明 |
|------|------|
| 查看方案 | 瀏覽可用的訂閱方案 |
| 購買訂閱 | 選擇方案並完成支付 |
| 查看狀態 | 查看當前訂閱和有效期 |
| 額度查詢 | 查看剩餘額度使用情況 |

## 常見問題

::: details 如何設置試用期？
創建一個價格為 0 的體驗方案，設置較短有效期（如 7 天），並設置購買上限為 1。
:::

::: details 用戶訂閱到期後會發生什麼？
- 用戶組會恢復到預設組（如果訂閱包含升級）
- 額度不再重置，剩餘額度可繼續使用
- 用戶可以續訂或購買新方案
:::

::: details 如何實現訂閱續費？
用戶在訂閱有效期內再次購買相同方案，有效期會自動延長。
:::

## 注意事項

::: warning 價格設置
- 確保價格金額與支付平臺配置一致
- 貨幣類型需與支付平臺支援幣種匹配
- 修改價格後需同步更新支付平臺的價格 ID
:::

::: tip 額度規劃
- 根據模型定價計算合理額度
- 設置重置週期時考慮用戶使用習慣
- 提供多種額度檔位滿足不同需求
:::

::: danger 方案禁用影響
- 禁用方案後，**新用戶無法購買**
- 已購買用戶**不受影響**，權益繼續生效
- 如需徹底下線，建議設置過渡期通知用戶
:::

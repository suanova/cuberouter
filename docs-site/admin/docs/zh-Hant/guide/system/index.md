# 系統設置

系統設置用於配置 CubeRouter 平臺的各項系統參數，包括運營設置、計費倍率、支付配置、性能監控、安全策略等。正確的系統配置是平臺穩定運行的基礎。

使用 Root 賬號登錄後，左側導航點擊「設置」，或直接訪問 `/console/setting`。

::: warning 權限要求
系統設置僅**超級管理員（Root）**可訪問，普通管理員無權修改。修改配置前請確保瞭解其影響。
:::

## 計費與倍率設置

倍率設置是 CubeRouter 計費系統的核心配置，通過設置不同的倍率可以靈活控制各種模型和用戶組的計費標準。

### 倍率系統概述

CubeRouter 使用三層倍率體系來計算用戶的配額消耗：

1. **模型倍率（ModelRatio）** - 定義不同 AI 模型的基礎計費倍數
2. **補全倍率（CompletionRatio）** - 對輸出 token 進行額外計費調整
3. **分組倍率（GroupRatio）** - 為不同用戶組設置差異化計費倍數

### 配額與倍率的關係

倍率是計算配額消耗的關鍵參數。配額是系統內部的計費單位，所有的 API 調用最終都會轉換為配額點數進行扣減。

**配額單位轉換：**

- 1 美元 = 500,000 配額點數
- 配額點數是系統內部計費的基礎單位
- 用戶的餘額、消費記錄都以配額點數為準

### 配額計算公式

#### 按量計費模型（基於 Token 消耗）

```text
配額消耗 = (輸入token數 + 輸出token數 × 補全倍率) × 模型倍率 × 分組倍率
```

#### 按次計費模型（固定價格）

```text
配額消耗 = 模型固定價格 × 分組倍率 × 配額單位(500,000)
```

#### 音頻模型（特殊處理，系統內部自動處理）

```text
配額消耗 = (文本輸入token + 文本輸出token × 補全倍率 + 音頻輸入token × 音頻倍率 + 音頻輸出token × 音頻倍率 × 音頻補全倍率) × 模型倍率 × 分組倍率
```

#### 預消費與後消費機制

平臺採用預消費和後消費的雙重計費機制：

1. **預消費階段**：API 調用前，根據預估 token 數計算配額消耗並預扣
2. **後消費階段**：API 調用完成後，根據實際 token 數重新計算配額消耗
3. **差額調整**：如果實際消耗與預消費不同，系統會自動調整用戶配額餘額

```text
預消費配額 = 預估token數 × 模型倍率 × 分組倍率
實際配額 = 實際token數 × 模型倍率 × 分組倍率
配額調整 = 實際配額 - 預消費配額
```

### 模型倍率設置

![計費與倍率設置標籤頁](/imgs/setting-ratio.png)

系統為各種模型預設了預設倍率：

| 模型名稱 | 模型倍率 | 補全倍率 | 官網價格（輸入） | 官網價格（輸出） |
| ------------- | -------- | -------- | ---------------- | ---------------- |
| gpt-4o | 1.25 | 4 | $2.5/1M Tokens | $10/1M Tokens |
| gpt-3.5-turbo | 0.25 | 1.33 | $0.5/1M Tokens | $1.5/1M Tokens |
| gpt-4o-mini | 0.075 | 4 | $0.15/1M Tokens | $0.6/1M Tokens |
| o1 | 7.5 | 4 | $15/1M Tokens | $60/1M Tokens |

**倍率含義說明：**

- 模型倍率：相對於基礎計費單位的倍數，反映模型的成本差異
- 補全倍率：輸出 token 相對於輸入 token 的計費倍數，反映輸出成本差異
- 倍率越高，消耗的配額越多；倍率越低，消耗的配額越少

**設置方法：**

1. 在系統設置頁點擊「倍率設置」標籤頁
2. 在模型倍率列表中找到目標模型

![模型倍率設置 - 頁面1](/imgs/rate-setting-1.png)

3. 修改以下參數：
   - **輸入倍率**：輸入 Token 的計費倍率
   - **輸出倍率**：輸出 Token 的計費倍率
   - **補全倍率**：補全接口的計費倍率

![模型倍率設置 - 頁面2](/imgs/rate-setting-2.png)

4. 點擊「保存」

![模型倍率設置 - 頁面3](/imgs/rate-setting-3.png)

**設置方式：**
1. JSON 格式設置：直接編輯模型倍率 JSON 配置
2. 可視化編輯器：通過圖形界面設置倍率

### 補全倍率設置

補全倍率用於對輸出 token 進行額外計費，主要用於平衡不同模型的輸入輸出成本差異。

| 模型類型 | 官網價格（輸入） | 官網價格（輸出） | 補全倍率 | 說明 |
| ------------- | ---------------- | ---------------- | -------- | --------------- |
| gpt-4o | $2.5/1M Tokens | $10/1M Tokens | 4 | 輸出是輸入的 4 倍 |
| gpt-3.5-turbo | $0.5/1M Tokens | $1.5/1M Tokens | 1.33 | 輸出 token 按輸入 1.33 倍計費 |
| gpt-image-1 | $5/1M Tokens | $40/1M Tokens | 8 | 輸出是輸入的 8 倍 |
| gpt-4o-mini | $0.15/1M Tokens | $0.6/1M Tokens | 4 | 輸出是輸入的 4 倍 |
| 其他模型 | 1 | 1 | 1 | 輸出是輸入的 1 倍 |

**設置說明：**

- 補全倍率主要影響輸出 token 的計費
- 設置為 1 表示輸出 token 計費與輸入 token 計費相同
- 大於 1 表示輸出 token 計費更高，小於 1 表示輸出 token 計費更低

### 分組倍率設置

分組倍率允許為不同用戶組設置差異化的計費倍數，實現靈活的定價策略。

#### 分組倍率配置

```json
{
  "vip": 0.5,
  "premium": 0.8,
  "standard": 1.0,
  "trial": 2.0
}
```

#### 分組倍率優先級

1. 用戶專屬倍率：為特定用戶設置的個人倍率
2. 分組倍率：用戶所屬分組的倍率
3. 預設倍率：系統預設倍率（通常為 1.0）

![分組倍率設置 - 頁面4](/imgs/rate-setting-4.png)

設置步驟：

1. 在倍率設置頁找到「分組倍率」區域
2. 選擇目標分組
3. 設置該分組的全局倍率係數（如 0.8 表示 8 折）

![分組倍率設置 - 頁面5](/imgs/rate-setting-5.png)

4. 點擊「保存」

分組倍率與模型倍率疊加計算：

```text
最終消耗 = Token 數量 × 模型倍率 × 分組倍率
```

### 可視化倍率設置

可視化編輯器提供了直觀的倍率管理界面，支援：

- 批量編輯模型倍率
- 實時預覽倍率配置
- 衝突檢測和提示
- 一鍵同步上游倍率

### 未設置倍率模型

對於未設置倍率的模型，系統會：

1. 自用模式：使用預設倍率 37.5
2. 商業模式：提示「倍率或價格未配置」錯誤
3. 自動檢測：在管理界面顯示未配置的模型

### 上游倍率同步

系統支援從上游渠道自動同步倍率設置：

- 自動獲取上游模型倍率
- 批量更新本地倍率配置
- 保持與上游價格同步
- 支援手動調整和覆蓋

### 常見問題

#### Q: 如何為新模型設置倍率？

A: 可以通過可視化編輯器添加新模型，或直接在 JSON 配置中添加。建議先設置保守倍率，根據實際使用情況調整。

#### Q: 分組倍率如何生效？

A: 分組倍率會與模型倍率相乘，最終影響用戶的配額消耗計算。用戶的實際倍率 = 模型倍率 × 分組倍率。

#### Q: 補全倍率的作用是什麼？

A: 補全倍率主要用於平衡輸入輸出 token 的成本差異。某些模型的輸出成本遠高於輸入成本，需要通過補全倍率進行調整。

#### Q: 如何批量設置相似模型的倍率？

A: 可以通過可視化編輯器進行批量操作，或者直接在 JSON 配置中批量添加相似模型的倍率設置。

### 配額計算實例

#### 示例1：GPT-4 標準用戶對話

場景參數：

- 輸入 token：1,000
- 輸出 token：500
- 模型倍率：15
- 補全倍率：2
- 分組倍率：1.0（標準用戶）

計算過程：

```
配額消耗 = (1,000 + 500 × 2) × 15 × 1.0
         = (1,000 + 1,000) × 15
         = 2,000 × 15
         = 30,000 配額點數
```

等價美元成本：30,000 ÷ 500,000 = $0.06

#### 示例2：GPT-3.5 VIP 用戶對話

場景參數：

- 輸入 token：2,000
- 輸出 token：1,000
- 模型倍率：0.25
- 補全倍率：1.33
- 分組倍率：0.5（VIP 用戶 50% 折扣）

計算過程：

```
配額消耗 = (2,000 + 1,000 × 1.33) × 0.25 × 0.5
         = (2,000 + 1,330) × 0.125
         = 3,330 × 0.125
         = 416.25 配額點數
```

等價美元成本：416.25 ÷ 500,000 = $0.00083

#### 示例3：按次計費模型（如 Midjourney）

場景參數：

- 模型固定價格：$0.02
- 分組倍率：1.0（標準用戶）
- 配額單位：500,000

計算過程：

```
配額消耗 = 0.02 × 1.0 × 500,000
         = 10,000 配額點數
```

等價美元成本：10,000 ÷ 500,000 = $0.02

## 註冊與安全設置

![註冊與安全設置標籤頁](/imgs/setting-security.png)

可配置以下內容：

- **開放註冊**：開關控制是否允許新用戶自行註冊。內部系統建議關閉，通過管理員創建賬戶

::: warning 註冊安全
- 公網服務建議開啓郵箱驗證，防止惡意註冊
- 可配合邀請碼系統控制註冊來源
:::

## OAuth 配置

### 內置 OAuth 提供商

![OAuth 設置標籤頁](/imgs/setting-oauth.png)

為需要啟用的第三方登錄平臺填寫對應的 Client ID 和 Client Secret：

| 提供商 | 說明 |
|--------|------|
| **GitHub** | GitHub 賬號登錄 |
| **Discord** | Discord 賬號登錄 |
| **微信** | 微信掃碼登錄 |
| **Telegram** | Telegram 賬號登錄 |
| **OIDC** | 通用 OpenID Connect 身份提供商 |

修改完成後點擊「保存」，用戶登錄頁即可看到對應的第三方登錄按鈕。

::: details OAuth 配置方法（以 GitHub 為例）
1. 訪問 GitHub → Settings → Developer settings → OAuth Apps
2. 創建新應用，填寫應用名稱和回調地址
3. 獲取 Client ID 和 Client Secret
4. 在系統設置中填入對應配置

**回調地址格式**：
```
https://your-domain.com/api/oauth/github/callback
```
:::

### OIDC 配置重要提示

::: warning OIDC 註冊
當啟用 OIDC 配置後，請一定要勾選「允許新用戶註冊」，否則會導致 OIDC 登錄的新用戶無法正常創建用戶，並同時勾選「允許通過 OIDC 進行登錄」。其他配置根據需要勾選。
:::

### 自定義 OAuth 提供商

除內置的 OAuth 提供商外，Root 可以添加任意符合 OIDC 標準的自定義登錄方式。

![自定義 OAuth 提供商列表](/imgs/custom-oauth-list.png)

**添加自定義 OAuth 提供商：**

1. 點擊「添加提供商」按鈕，彈出配置彈窗

![添加自定義 OAuth 彈窗](/imgs/custom-oauth-add.png)

2. 在「Discovery URL」輸入框中填寫 OIDC 提供商的 Discovery 地址（通常以 `/.well-known/openid-configuration` 結尾），點擊「自動發現」，系統自動填充 Authorization Endpoint、Token Endpoint 等配置

![自動發現填充後的配置項](/imgs/custom-oauth-filled.png)

3. 填寫 Client ID 和 Client Secret（從 OAuth 提供商的應用管理頁面獲取）
4. 填寫顯示名稱（用戶在登錄頁看到的按鈕文字）
5. 點擊「保存」，配置完成後用戶登錄頁出現該提供商的登錄入口

::: tip OIDC vs OAuth
OIDC 是 OAuth 2.0 的擴展，提供標準化的用戶資訊獲取方式。如果您的身份提供商支援 OIDC，建議使用 OIDC 而非自定義 OAuth 配置。
:::

## 郵件伺服器配置

配置郵件伺服器用於發送驗證碼、通知等郵件。

![系統設置 - 郵件伺服器](/imgs/system-setting-2.png)

1. 在系統設置頁找到「郵件伺服器」配置區域
2. 填寫以下資訊：
   - **SMTP 伺服器地址**：郵件伺服器地址（如 smtp.gmail.com）
   - **SMTP 端口**：通常為 465（SSL）或 587（TLS）
   - **發件人郵箱**：用於發送郵件的郵箱地址
   - **發件人名稱**：郵件中顯示的發件人名稱
   - **SMTP 用戶名**：通常與發件人郵箱相同
   - **SMTP 密碼**：郵箱的授權密碼或應用專用密碼
3. 點擊「測試郵件」驗證配置是否正確
4. 點擊「保存」

::: info Gmail 應用專用密碼
Gmail 等郵箱需要使用應用專用密碼，而不是賬號密碼。請在郵箱設置中生成應用專用密碼。
:::

## 支付設置

配置平臺支援的支付方式和支付參數。

![支付設置頁面](/imgs/payment-setting.png)

### 什麼是易支付

`易支付`是對「第三方聚合收款網關/接口」模式的泛稱，並非某一傢俱體的網站或公司。既可指商用聚合支付服務，也可指自建/開源、遵循「易支付協議風格」的網關實現。

**核心作用：** 聚合微信支付、支付寶、銀行卡等渠道，向商戶提供統一的下單、簽名校驗與回調接口。

::: warning 合規提示
網關本身不等同於持牌支付機構；資金清結算與合規依賴其對接的持牌渠道，請遵循所在地監管與風控要求。
:::

### EPay 配置

### 充值方式設置

在「充值方式」中，可按以下結構配置：

```json
[
  {
    "color": "rgba(var(--semi-blue-5), 1)",
    "name": "支付寶",
    "type": "alipay"
  },
  {
    "color": "rgba(var(--semi-green-5), 1)",
    "name": "微信",
    "type": "wxpay"
  },
  {
    "color": "rgba(var(--semi-green-5), 1)",
    "name": "Stripe",
    "type": "stripe",
    "min_topup": "50"
  },
  {
    "name": "自定義1",
    "color": "black",
    "type": "custom1",
    "min_topup": "50"
  }
]
```

**字段說明**

- **name**：展示文案。顯示在「選擇支付方式」的按鈕上（如「支付寶/微信/Stripe/自定義1」）
- **color**：按鈕/徽標的主題色或邊框色。支援任意 CSS 顏色值，推薦使用現有設計令牌（如 `rgba(var(--semi-blue-5), 1)`）
- **type**：通道標識，用於後端路由與下單
  - `stripe` → 走 Stripe 網關
  - 其他（如 `alipay`、`wxpay`、`custom1` 等）→ 走易支付風格網關，並將該值作為渠道參數透傳
- **min_topup**：最低充值金額（單位與頁面貨幣一致）。當輸入金額小於該值時，頁面會提示「此支付方式最低充值金額為 X」，並限制發起支付；後端也會進行校驗
- **排序**：按數組順序從左到右渲染

## 限流設置

配置 API 調用的頻率限制，防止濫用和保護系統穩定性。

![限流設置頁面](/imgs/rate-limit-setting.png)

### 全侷限流

1. 在系統設置頁點擊「限流設置」標籤頁
2. 配置全侷限流參數：
   - **每分鐘請求數**：單個 IP 每分鐘最多請求次數
   - **每小時請求數**：單個 IP 每小時最多請求次數
   - **每天請求數**：單個 IP 每天最多請求次數
3. 點擊「保存」

### 按用戶分組限流

可以為不同用戶分組設置不同的限流策略：

1. 在分組管理頁編輯分組
2. 設置該分組的限流參數
3. 分組內所有用戶共享該限流配置

#### 分組速率限制配置示例

```json
{
  "default": [200, 100],
  "vip": [0, 1000]
}
```

**配置說明：**

- **鍵**：分組名稱
- **值**：數組，包含兩個數字
  - 第一個數字：每分鐘請求數限制
  - 第二個數字：每小時請求數限制
  - 設置為 0 表示不限制

**示例解釋：**

- `default` 分組：每分鐘最多 200 次請求，每小時最多 100 次請求
- `vip` 分組：每分鐘不限制，每小時最多 1000 次請求

### 限流超限響應

當用戶超出限流閾值時：

```json
{
  "error": {
    "message": "Rate limit exceeded. Please retry after 60 seconds.",
    "type": "rate_limit_error",
    "code": "rate_limit_exceeded"
  }
}
```

::: warning 限流策略建議
- 新用戶設置較低的限額，防止濫用
- VIP 用戶可設置更高限額
- 限流設置過低可能影響正常使用，建議根據實際業務需求合理配置
:::

| 配置項 | 說明 | 預設值 |

### Passkey（通行金鑰）設置

Passkey 是基於 WebAuthn 的無密碼認證方式，支援指紋、Face ID、硬件金鑰等。

| 配置項 | 說明 | 預設值 |
|--------|------|--------|
| **啟用 Passkey** | 是否啟用 Passkey 登錄 | 關閉 |
| **顯示名稱** | 認證時顯示的服務名稱 | CubeRouter |
| **RP ID** | 依賴方標識，通常為域名 | 自動從伺服器地址獲取 |
| **來源** | 允許的來源地址列表 | 自動從伺服器地址獲取 |
| **允許不安全來源** | 是否允許 HTTP 來源（僅開發環境） | 關閉 |
| **用戶驗證方式** | 用戶驗證級別 | `preferred` |
| **附件偏好** | 認證器偏好設置 | 空 |

::: details Passkey 配置說明
**RP ID 和來源**：
- RP ID 通常是您的域名（不含協議和端口）
- 來源是完整的 URL 列表，JSON 數組格式
- 生產環境必須使用 HTTPS

**用戶驗證方式**：
- `preferred`：優先使用生物識別
- `required`：必須使用生物識別
- `discouraged`：不推薦使用生物識別
:::

![首頁左側導航出現「文件」按鈕的效果](/imgs/setting-docs-effect.png)

::: info 文件按鈕顯示條件
文件地址留空時，左側導航不會顯示「文件」按鈕。
:::

#### 配置關於頁

1. 在系統設置頁點擊「其它設置」標籤頁
2. 找到「關於」內容編輯區域

![關於內容編輯區](/imgs/setting-about-editor.png)

4. 點擊「保存」
5. 用戶點擊左側導航「關於」後將看到配置的內容

![關於頁展示效果](/imgs/setting-about-effect.png)

## 操作指南

### 修改配置

1. 進入對應的設置標籤頁
2. 找到需要修改的配置項
3. 修改配置值
4. 點擊 **保存** 按鈕
5. 根據提示判斷是否需要重啓服務

::: warning 配置生效方式

| 配置類型 | 生效方式 |
|----------|----------|
| 運營設置 | 立即生效 |
| 性能設置 | 需重啓服務 |
| 支付設置 | 立即生效 |
| 安全設置 | 立即生效 |

:::

### 重置配置

如需恢復預設配置：

1. 點擊配置項旁邊的 **重置** 按鈕
2. 確認重置操作

### 環境變量配置

部分敏感配置建議通過環境變量設置：

```bash
# 數據庫
SQL_DSN=your-database-dsn

# Redis
REDIS_URL=redis://localhost:6379

# Stripe
STRIPE_SECRET_KEY=sk_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx

# GitHub OAuth
GITHUB_CLIENT_ID=xxx
GITHUB_CLIENT_SECRET=xxx
```

## 注意事項

::: danger 金鑰安全
- API Key、Secret 等敏感資訊請妥善保管
- 不要在代碼倉庫中提交金鑰
- 定期輪換金鑰
- 使用環境變量而非配置文件存儲金鑰
:::

::: tip 配置管理建議
- 修改配置前記錄原值
- 重要配置變更先在測試環境驗證
- 定期備份配置
- 變更後進行功能測試
:::

::: info 重啓服務
以下配置修改後需要重啓服務：
- 伺服器地址、端口
- 併發請求數、連接池大小
- Redis 配置
- 日誌級別
:::

# 渠道管理

渠道管理是 CubeRouter 的核心功能，用於配置和管理各類 AI 模型提供商的 API 接入渠道。每條渠道對應一個服務商的 API Key，通過渠道管理，管理員可以靈活地添加、編輯、測試和監控多個 AI 服務提供商。

使用管理員賬號登錄後，左側導航點擊「渠道」，或直接訪問 `/console/channel`。

::: warning 合規提示
上游渠道必須是部署方合法擁有或已獲授權的賬號、API Key、模型服務或企業合約。負載均衡、故障自動切換、加權隨機、多金鑰管理等功能用於高可用和企業多賬號管理，使用時應遵守上游服務條款、平臺規則和監管要求。
:::

## 渠道配置

### 基本配置

1. 在渠道列表頁點擊右上角「添加渠道」按鈕，彈出配置彈窗
2. 在彈窗中選擇服務商類型（如 OpenAI、Claude、Gemini 等）
3. 填寫渠道名稱和 API Key

![添加渠道彈窗(基礎資訊)](/imgs/channel-add-basic.png)

| 字段 | 必填 | 說明 |
|------|:----:|------|
| **渠道名稱** | ✓ | 渠道的顯示名稱，便於識別和管理 |
| **渠道類型** | ✓ | AI 服務提供商類型 |
| **API Key** | ✓ | 服務提供商的 API 金鑰 |
| **Base URL** | | 自定義 API 端點地址 |
| **模型列表** | ✓ | 該渠道支援的模型 |
| **用戶組** | | 可訪問該渠道的用戶組 |

### 選擇模型

在模型列表中勾選該渠道支援的模型，或點擊「填入預設模型」自動填充。

### 高級配置

按需展開高級配置，填寫以下可選項：

![添加渠道彈窗(高級配置)](/imgs/channel-add-advanced.png)

| 配置項 | 說明 |
| --- | --- |
| Base URL | 自定義接口地址，代理或私有部署時使用 |
| 優先級 | 數值越高越優先被選中，預設為 0 |
| 權重 | 同優先級下的隨機權重，預設為 0 |
| 模型映射 | 將用戶請求的模型名映射為實際模型名，JSON 格式 |
| 參數覆蓋 | 強制覆蓋請求中的某些參數，JSON 格式 |
| 自動禁用 | 開啓後連續失敗達到閾值時自動禁用該渠道 |

## 多 Key 模式

多 Key 模式允許一個渠道配置多個 API Key，系統自動輪詢使用，單個 Key 失敗後自動跳過，恢復後重新啟用。

### 配置多 Key

1. 在渠道列表中點擊目標渠道右側的「編輯」按鈕
2. 在編輯彈窗中找到「多 Key 管理」區域

![多 Key 模式配置區域](/imgs/channel-multikey.png)

3. 點擊「添加 Key」逐條輸入多個 API Key

### 選擇輪詢模式

| 輪詢模式 | 說明 |
| --- | --- |
| **輪詢（Round Robin）** | 按順序依次使用每個 Key |
| **加權隨機** | 按權重隨機選擇 Key |

::: tip 多 Key 最佳實踐
- 建議配置 2-3 個 Key 以保障可用性
- 定期檢查各 Key 的使用量和餘額
- 不同 Key 可以來自不同賬戶，分散風險
:::

### 保存配置

點擊「保存」完成配置。

## 渠道狀態

| 狀態 | 圖標 | 說明 | 處理建議 |
|------|:----:|------|----------|
| **已啟用** | 🟢 | 正常工作，處理請求 | 無需操作 |
| **已禁用** | 🔴 | 手動禁用，不處理請求 | 按需啟用 |
| **自動禁用** | 🟡 | 連續失敗被系統禁用 | 檢查 Key 有效性或餘額 |

::: warning 自動禁用機制
當渠道連續請求失敗達到閾值時，系統會自動禁用該渠道。常見原因：

- API Key 失效或過期
- 賬戶餘額不足
- 上游服務異常
- 請求頻率超限

被自動禁用的渠道需手動重新啟用，或在修復問題後自動恢復（取決於配置）。
:::

## 渠道測試

### 單個渠道測試

1. 在渠道列表中找到目標渠道，點擊右側操作欄中的「測試」按鈕
2. 等待測試請求完成，彈窗顯示響應時間和成功/失敗狀態

![渠道測試結果彈窗](/imgs/channel-test.png)

響應時間越短說明該渠道速度越快。測試成功後，響應時間會顯示在渠道列表中，便於監控渠道性能。

### 批量測試

點擊列表頂部「測試所有渠道」按鈕一鍵批量測試。

::: tip 測試建議
- 新建渠道後立即測試，確保配置正確
- 定期測試渠道，及時發現異常
- 關注響應時間變化，評估服務質量
:::

## 權限設置

渠道支援按用戶組進行訪問控制：

| 用戶組 | 說明 |
|--------|------|
| **default** | 預設用戶組，所有用戶可訪問 |
| **vip** | VIP 用戶組，僅 VIP 用戶可訪問 |
| **自定義組** | 管理員創建的自定義用戶組 |

::: info 權限控制原理
用戶請求模型時，系統會根據用戶所屬的用戶組篩選可用的渠道。只有渠道配置的用戶組與用戶組匹配時，該渠道纔會被納入路由選擇。
:::

## 模型映射

模型映射允許將用戶請求的模型名稱映射到實際使用的模型：

```json
{
  "gpt-4": "gpt-4-turbo",
  "gpt-3.5-turbo": "gpt-3.5-turbo-16k"
}
```

**常見用途**：
- 模型升級後保持兼容性（`gpt-4` → `gpt-4-turbo`）
- 統一不同提供商的模型命名
- 為用戶提供簡化的模型名稱

詳見 [高級設置 - 模型映射](./advanced#模型映射)

## 操作指南

### 新建渠道

1. 點擊頁面右上角的 **新建渠道** 按鈕
2. 選擇渠道類型
3. 填寫必要資訊：
   - 渠道名稱
   - API Key
   - 支援的模型
4. 配置可選參數：
   - 用戶組權限
   - Base URL（代理或私有部署時需要）
5. 點擊 **提交** 保存

### 編輯渠道

1. 在渠道列表中找到目標渠道
2. 點擊 **編輯** 按鈕
3. 修改需要更新的配置
4. 點擊 **保存** 確認修改

### 批量操作

支援選中多個渠道後進行批量操作：

1. 在渠道列表左側勾選多條渠道的複選框
2. 頁面頂部出現批量操作工具欄

![勾選多條渠道後的批量操作欄](/imgs/channel-batch.png)

3. 點擊對應按鈕執行批量操作：

| 操作 | 說明 |
|------|------|
| **批量啟用** | 一次性啟用多個渠道 |
| **批量禁用** | 一次性禁用多個渠道 |
| **批量打標籤** | 為選中渠道統一設置標籤，便於分類管理 |
| **批量刪除** | 刪除選中的渠道（不可恢復） |

::: danger 批量刪除警告
批量刪除操作不可恢復，請謹慎操作。建議先禁用觀察，確認無誤後再刪除。
:::

## 注意事項

::: warning API Key 安全
- 不要在公開場合分享 API Key
- 定期輪換 API Key
- 使用環境變量或金鑰管理服務存儲 Key
:::

::: tip 運維建議
- **餘額監控**：定期檢查渠道餘額，避免服務中斷
- **響應時間**：關注渠道響應時間變化，及時發現性能問題
- **多渠道備份**：關鍵模型配置多個渠道，保障服務可用性
- **標籤分類**：使用標籤對渠道分類，便於管理大量渠道
:::
